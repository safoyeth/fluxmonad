# Архитектура и внутреннее устройство FluxMonad

**[English](architecture.md)** | **[Русский](architecture_ru.md)**

FluxMonad — это высокопроизводительная библиотека ленивой потоковой обработки данных для Python 3.10+. Она объединяет строгие формальные гарантии функциональных монад, эргономику декларативных конструкторов запросов (в стиле Django / LINQ) и производительность оптимизатора графа выполнения на основе правил (RBO).

---

## 1. Основные принципы

```
  Загрузка данных (Iterable / CSV / JSON / YAML / TOML / Excel)
                             │
                             ▼
              Построение графа пайплайна (AST)
           [ SourceNode → TransformNodes → Terminal ]
                             │
                             ▼
         Оптимизатор на основе правил (RBO Optimizer)
             [ Predicate Pushdown, Node Fusion ]
                             │
                             ▼
                Ленивое вычисление итератора
          [ O(1) расход памяти, потоковый yield ]
```

1. **Строгая ленивость и ограниченная память**: Операции не выполняются в момент вызова методов. Вызовы формируют направленную ациклическую цепочку узлов (`Node`). Записи извлекаются генератором последовательно по одной, что гарантирует строго ограниченный объем используемой памяти ($O(1)$ для чисто потоковых конвейеров).
2. **Законы монадических конвейеров**: `Flux` полностью удовлетворяет законам монад (Left Identity, Right Identity, Associativity), позволяя компоновать преобразования через метод `bind` и оператор `>>`.
3. **Разделение построения и выполнения плана**: Конструирование конвейера формирует абстрактное синтаксическое дерево (AST) из экземпляров `Node`. При вызове терминальных операций (`__iter__`, `collect`, `first`, `sum` и др.) граф перед исполнением передается в `PlanOptimizer.optimize()`.
4. **Прозрачная семантика барьеров**: Операции, требующие полной материализации данных (такие как `SortNode`, `GroupByNode`, `ReverseNode`), объявляют флаг `is_barrier = True`. Оптимизатор запросов строго учитывает границы барьеров, предотвращая некорректную перестановку узлов.

## 2. Соответствие законам монад

В теории категорий и функциональном программировании монада $(M, \text{unit}, \text{bind})$ обязана удовлетворять трем фундаментальным законам:

### 2.1 Левая единица (Left Identity)
Передача значения $a$ в unit с последующим связыванием с функцией $f$ эквивалентна прямому вызову $f(a)$:
$$\text{unit}(a) \gg= f \equiv f(a)$$

В FluxMonad:
```python
a = 5
f = lambda x: Flux([x, x * 2])

left = (Flux([a]) >> f).collect()   # [5, 10]
right = f(a).collect()              # [5, 10]
assert left == right
```

### 2.2 Правая единица (Right Identity)
Связывание монадического значения с `Flux.unit` (или конструктором) возвращает исходную монаду без изменений:
$$m \gg= \text{unit} \equiv m$$

В FluxMonad:
```python
m = Flux([1, 2, 3])
unit = lambda x: Flux([x])

assert (m >> unit).collect() == [1, 2, 3]
```

### 2.3 Ассоциативность (Associativity)
Результат цепочки связываний не зависит от порядка группировки скобок:
$$(m \gg= f) \gg= g \equiv m \gg= (\lambda x. f(x) \gg= g)$$

В FluxMonad:
```python
m = Flux([1, 2, 3])
f = lambda x: Flux([x, x + 10])
g = lambda y: Flux([y, y * 100])

left = ((m >> f) >> g).collect()
right = (m >> (lambda x: f(x) >> g)).collect()
assert left == right
```

## 3. Иерархия узлов (Node Hierarchy)

Все преобразования данных наследуются от базового абстрактного класса `fluxmonad.plan.node.Node`:

```
Node (абстрактный базовый класс)
 ├── SourceNode
 ├── Трансформирующие узлы (is_barrier = False)
 │    ├── MapNode
 │    ├── FilterNode
 │    ├── SelectNode / ExcludeNode
 │    ├── TakeNode / SkipNode
 │    ├── ExtendNode / RenameNode
 │    ├── ZipNode
 │    ├── TapNode
 │    ├── ChunkNode / WindowNode
 │    ├── FlattenNode / FillNullNode
 │    ├── BranchNode / CatchNode / CompactNode
 │    └── ParallelMapNode
 ├── Аналитические узлы (is_barrier = False, ограниченное состояние)
 │    ├── EnumerateNode
 │    ├── CumulativeSumNode
 │    └── LagLeadNode (ограниченный deque размера offset)
 └── Барьерные узлы (is_barrier = True)
      ├── SortNode
      ├── GroupByNode
      ├── DistinctNode
      ├── ReverseNode
      ├── SampleNode (Reservoir sampling)
      ├── JoinNode / CrossJoinNode
      └── IntersectionNode / DifferenceNode
```

### 3.1 Потоковые узлы (`is_barrier = False`)
Потоковые узлы реализуют интерфейс `evaluate() -> Iterator[Any]` через генераторы или модуль `itertools`. Они обрабатывают каждый элемент с константным расходом памяти $O(1)$ и поддерживают раннюю остановку (например, `take(n)` мгновенно завершает поток после получения $n$ записей).

### 3.2 Барьерные узлы (`is_barrier = True`)
Барьерным узлам требуется полностью аккумулировать входящий поток элементов до выдачи первого результата:
- **`SortNode`**: Материализует входящий поток в список, выполняет Timsort средствами C-ядра Python с поддержкой ASC/DESC компараторов и возвращает итератор по отсортированному результату.
- **`GroupByNode`**: Считывает поток в `defaultdict(list)`, группируя элементы с сохранением исходного порядка появления ключей. Генерирует объекты `Group(key, values)` с изолированными вложенными потоками.
- **`SampleNode`**: Реализует **Алгоритм R (Reservoir Sampling)**, сохраняя ровно $n$ случайных элементов с равномерной вероятностью в памяти объемом $O(n)$ независимо от того, содержит ли источник $10^6$ или $10^9$ строк.

## 4. Движок AST-выражений

Вместо непрозрачных функций `lambda`, структуру которых невозможно проанализировать до исполнения, FluxMonad предоставляет компонуемый движок выражений (`Field`, `Q`, `Expression`):

```python
from fluxmonad import Field, Q

# Перегрузка операторов в AST:
expr1 = (Field("age") >= 18) & (Field("status") == "active")

# Выражения в стиле Django Q:
expr2 = Q(age__gte=18, status="active") | Q(role="admin")
```

Каждый объект `Expression` предоставляет:
- `evaluate(item) -> bool`: Вычисляет предикат над словарем, объектом или mapping-структурой с использованием кэшированных резолверов путей.
- `referenced_fields -> set[str]`: Анализирует, какие поля требуются для вычисления выражения. Эти метаданные являются основой работы оптимизатора **Predicate Pushdown**.
- `explain() -> str`: Формирует человекочитаемое строковое представление для отладки графа.

## 5. Универсальный доступ к свойствам и резолверы

FluxMonad обеспечивает единообразный синтаксис доступа к полям гетерогенных структур данных Python:
- Ключи словаря: `get_value(data, "user.name")`
- Атрибуты объектов: `get_value(obj, "user.address.city")`
- Индексы последовательностей: `get_value(data, "items.0.price")`
- Глубокий рекурсивный поиск (синтаксис `..`): `get_value(data, "meta..token")` рекурсивно ищет ключ в структуре словарей и атрибутов с помощью поиска в глубину (DFS) и LRU-кэшированием путей.
