# Оптимизация планов выполнения и проталкивание предикатов

**[English](optimization.md)** | **[Русский](optimization_ru.md)**

FluxMonad оснащен встроенным **оптимизатором на основе правил (Rule-Based Optimizer, RBO)**, реализованным в классе `PlanOptimizer`. Оптимизатор анализирует граф выполнения конвейера и применяет алгебраические преобразования до того, как данные начнут извлекаться из источника.

---

## 1. Что такое проталкивание предикатов (Predicate Pushdown)?

В наивных потоковых конвейерах тяжелые вычисления часто производятся для всех строк подряд, хотя многие из них затем отбрасываются последующими фильтрами:

```
Наивное выполнение (без оптимизатора):
  Источник (1 000 000 записей)
      ↓
  Тяжелые вычисления / Extend (выполняются для 1 000 000 записей)  ← 100% затрат CPU
      ↓
  Фильтр ('age >= 90') (отбрасывает 90% записей)
      ↓
  Результат (100 000 записей)
```

Благодаря **проталкиванию предикатов (Predicate Pushdown)** FluxMonad статически перемещает узел `FilterNode` перед независимыми от него преобразованиями:

```
Оптимизированное выполнение (с Predicate Pushdown):
  Источник (1 000 000 записей)
      ↓
  Фильтр ('age >= 90') (СНАЧАЛА отсекает 900 000 записей)        ← Дешевая проверка
      ↓
  Тяжелые вычисления / Extend (выполняются ТОЛЬКО для 100 000)   ← Экономия 90% CPU!
      ↓
  Результат (100 000 записей)
```

В тестовом сценарии бенчмарка №2 эта оптимизация обеспечивает **сокращение времени выполнения более чем на 54%**.

## 2. Анализ безопасности зависимостей (`_can_swap`)

Оптимизация корректна тогда и только тогда, когда она гарантированно не меняет семантический результат работы программы. FluxMonad выполняет строгую проверку зависимостей перед перестановкой узла `FilterNode` с предшествующим узлом:

### 2.1 Перестановка через `ExtendNode`
- Оптимизатор инспектирует множество `filter_node.expr.referenced_fields`.
- Если вычисляемое поле, создаваемое `ExtendNode` (например, `token`), входит в `referenced_fields`, то фильтр **зависит** от него и **не может быть перемещен выше**:
  ```python
  # Фильтр ЗАВИСИТ от поля 'token': перестановка ЗАПРЕЩЕНА
  Flux(data).extend("token", heavy_func).when(Field("token").contains("abc"))
  ```
- Если предикат проверяет независимые поля (например, `age >= 18`), перестановка абсолютно безопасна:
  ```python
  # Фильтр зависит от 'age', а не от 'token': ПРОТАЛКИВАЕТСЯ ВЫШЕ
  Flux(data).extend("token", heavy_func).when(Field("age") >= 18)
  ```

### 2.2 Перестановка через `RenameNode`
- Если исходное или новое имя поля в словаре переименования пересекается с зависимостями фильтра, перестановка узлов без модификации предиката невозможна. FluxMonad сохраняет исходный порядок.

### 2.3 Перестановка через `TapNode`
- Узел `TapNode` не мутирует проходящие данные. Фильтры всегда могут безопасно перемещаться через `TapNode`.

### 2.4 Учет границ барьеров
- Фильтры никогда не перемещаются через барьерные узлы (`SortNode`, `GroupByNode`, `ReverseNode`) или через узел источника `SourceNode`.

## 3. Правила слияния узлов (Node Fusion)

Соседние узлы одного типа алгебраически объединяются в единые составные узлы:

### 3.1 Слияние Take (Take Fusion)
Несколько последовательных ограничений `take` схлопываются в минимальное значение:
$$\text{Take}(n_1) \circ \text{Take}(n_2) \implies \text{Take}(\min(n_1, n_2))$$

Если встречается `take(0)`, весь конвейер схлопывается в пустой `SourceNode([])`, предотвращая лишнее чтение источника.

### 3.2 Слияние Skip (Skip Fusion)
Последовательные пропуски суммируются:
$$\text{Skip}(s_1) \circ \text{Skip}(s_2) \implies \text{Skip}(s_1 + s_2)$$

### 3.3 Слияние Filter (Filter Fusion)
Соседние предикаты фильтрации объединяются логическим оператором `And`:
$$\text{Filter}(P_1) \circ \text{Filter}(P_2) \implies \text{Filter}(P_1 \land P_2)$$

Это снижает накладные расходы на вызовы промежуточных генераторов и переключение контекста.

## 4. Визуализация плана с помощью `explain()`

Вы можете наглядно изучить как исходный, так и оптимизированный граф выполнения с помощью метода `.explain()`:

```python
from fluxmonad import Flux, Field

pipeline = (
    Flux(range(1000))
    .extend("heavy_token", lambda x: str(x) * 10)
    .when(Field("value") > 500)
    .take(20)
    .take(5)
)

print(pipeline.explain(optimized=False))
# Flux execution plan
# SOURCE: range
#   ↓
# EXTEND: heavy_token
#   ↓
# FILTER: value > 500
#   ↓
# TAKE: 20
#   ↓
# TAKE: 5

print(pipeline.explain(optimized=True))
# Flux execution plan
# SOURCE: range
#   ↓
# FILTER: value > 500      <-- Протолкнут перед EXTEND
#   ↓
# EXTEND: heavy_token
#   ↓
# TAKE: 5                  <-- Узлы 20 и 5 объединены в 5
```
